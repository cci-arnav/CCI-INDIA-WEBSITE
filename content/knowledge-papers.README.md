# Adding knowledge papers

Add a published paper by creating one catalogue record in `content/knowledge-papers.json`. Optional public cover artwork may be placed in `public/images/knowledge-papers/`.

Never add an original PDF, private Storage path, or full-PDF URL to the public repository or catalogue. Visitors can read a server-generated preview of at most the first five pages without signing in. Original PDFs must remain in the private Supabase `knowledge-papers-private` bucket; the server-side reader returns only the generated preview. Requests for full papers go through the existing prefilled Google Form and are handled by CCI India outside the website.

To enable reading for a catalogue record, verify the existing Supabase setup before any schema changes, configure the server-only `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` variables in Vercel, upload the original PDF to the private bucket, and register its stable catalogue `id` and exact bucket object path in `public.knowledge_papers_private`. The public API always emits at most five pages and does not accept a client-selected preview limit. Do not make the bucket public or create public full-PDF URLs. The repository does not include original PDFs, so papers remain unavailable in the reader until deliberately onboarded. The runtime does not implement user accounts, online access requests, per-user grants, or full-paper delivery.

For local testing, enter the project URL as `SUPABASE_URL` and the server-side service-role credential as `SUPABASE_SERVICE_ROLE_KEY` in the ignored `.env.local` file. Obtain both from the Supabase Dashboard for the intended project; never send the credential in chat, commit it, or give it a `VITE_` prefix. Start the local API with `npm run dev:vercel`. The endpoint returns sanitized JSON diagnostic codes for configuration, registry, Storage, and invalid-PDF failures; it never includes credentials or private object paths.

The paper-specific Google Form URL is configured in `src/lib/knowledgePapers.js`; it pre-fills the title and collection. Keep this route available until preview delivery has been tested against the configured private bucket.

The 109-entry source coverage report is generated by `node scripts/build-knowledge-paper-coverage.mjs` and written to `content/knowledge-paper-coverage.json`. It preserves every catalogue ID, records existing catalogue source metadata, captures Drive folder listings and locally audited PDFs, and keeps uncertain filename matches in review status. Drive listings alone do not count as readable/verified PDFs. `scripts/knowledge-paper-source-manifest.json`, `scripts/knowledge-paper-drive-listings.json`, and `scripts/knowledge-paper-embassy-pdf-audit.json` are read-only audit inputs; none authorizes an upload or creates a Storage path. Update the audit inputs only from verified source files or observed Drive listings, then regenerate the coverage report.

Each record should use a stable, unique `id` and include `title`, `country`, `countryCode` (two-letter ISO code), `collection`, `publishedAt` (`YYYY-MM-DD`), `accessMode: "request"`, and `published: true`. Optional fields are `subject`, `region`, `description`, `year`, `coverImage`, `fileSize`, `tags`, and `featured`.

Example shape (documentation only; this is not displayed):

```json
{
  "id": "stable-paper-slug",
  "title": "Verified paper title",
  "country": "Country name",
  "countryCode": "IN",
  "region": "South Asia",
  "collection": "International & Sectoral",
  "description": "Short summary",
  "publishedAt": "2026-09-01",
  "year": 2026,
  "coverImage": "/images/knowledge-papers/verified-cover.webp",
  "fileSize": "2.4 MB",
  "tags": ["Trade", "Investment"],
  "featured": false,
  "accessMode": "request",
  "published": true
}
```
