# Adding knowledge papers

Add a published paper by creating one catalogue record in `content/knowledge-papers.json`. Optional public cover artwork may be placed in `public/images/knowledge-papers/`.

Never add an original PDF, private source path, or full-PDF URL to the public repository or catalogue. The reader loads only pre-generated static preview PDFs from `public/knowledge-papers/`; each preview is limited to the first 10 pages. The original full PDFs must not be copied into the public assets directory. Requests for full papers go through the existing prefilled Google Form and are handled by CCI India outside the website.

To add a static preview, add the validated, rasterized preview PDF at `public/knowledge-papers/<catalogue-id>.pdf` and add its URL, original source page count, and preview page count to `src/data/knowledgePaperPreviewRegistry.json`. The browser loads that public PDF directly and enforces the 10-page limit. Do not add server API, private-storage, or runtime PDF-generation dependencies to the reader. If a record has no verified preview, leave it out of the registry; its route will show an unavailable-preview message and the full-paper request form.

For the current imported set, `node scripts/publish-static-knowledge-paper-previews.mjs` validates and copies the 125 canonical previews already present under the ignored `private-knowledge-papers/previews/` directory. It deliberately omits the six ambiguous alternate editions. See `docs/knowledge-paper-previews.md` for the exact three catalogue IDs that remain without previews and the focused validation test.

The paper-specific Google Form URL is configured in `src/lib/knowledgePapers.js`; it pre-fills the title and collection. Keep this route available for every paper, including catalogue records without a static preview.

The 109-entry source coverage report is generated by `node scripts/build-knowledge-paper-coverage.mjs` and written to `content/knowledge-paper-coverage.json`. It preserves every catalogue ID, records existing catalogue source metadata, captures Drive folder listings and locally audited PDFs, and keeps uncertain filename matches in review status. Drive listings alone do not count as readable/verified PDFs. `scripts/knowledge-paper-source-manifest.json`, `scripts/knowledge-paper-drive-listings.json`, and `scripts/knowledge-paper-embassy-pdf-audit.json` are read-only audit inputs; none authorizes an upload or creates a Storage path. Update the audit inputs only from verified source files or observed Drive listings, then regenerate the coverage report.

Each record should use a stable, unique `id` and include `title`, `country`, `countryCode` (two-letter ISO code), `collection`, `publishedAt` (`YYYY-MM-DD`), `accessMode: "request"`, and `published: true`. Optional fields are `subject`, `region`, `description`, `year`, `coverImage`, `fileSize`, `tags`, and `featured`.

Example shape (documentation only; this is not displayed):

```json
{
  "id": "stable-paper-slug",
  "title": "Verified paper title",
  "country": "Country name",
  "countryCode": "IN",
  "region": "South Asia",
  "collection": "International & Sectoral",
  "description": "Short summary",
  "publishedAt": "2026-09-01",
  "year": 2026,
  "coverImage": "/images/knowledge-papers/verified-cover.webp",
  "fileSize": "2.4 MB",
  "tags": ["Trade", "Investment"],
  "featured": false,
  "accessMode": "request",
  "published": true
}
```
